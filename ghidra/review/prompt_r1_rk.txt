Review of provisional function names in a game decompile: Rakugaki Showtime (Treasure / Enix, 1999, PlayStation, program HAGECHO.BIN loaded from a RAM dump, MIPS R3000 with GTE, PsyQ GCC). Research only.
These names were marked provisional by a first naming pass. Now each entry also has its callers.
Entry layout: "#### PROG 0x<addr> <name> | <comment>", then the function decompile, then "---- callers: N (names)", then up to 3 caller decompiles.
Names of callees are already substituted where known. Program SCUS = the main ELF (.text 0x00140000; FPS on Vekta vs the Helghast; levels streamed from FILES.DAT packs; overlays BLGFX/NETWORK/ONLINE/DNASMC .REL; Sony libs sceGs, sceDma, scePad, sceCd, sceSif RPC, sceVu0, libc, libm).
Ghidra decoded the ELF as generic MIPS64: R5900 MMI / VU0 macro ops (qmtc2, qmfc2, lq, sq, paddw, pextlw) show as bad instructions, halt_baddata() or odd 64-bit code; such functions are vector math, matrix or DMA packet code, not bugs.
Name from what the code does; never copy text from any leaked source.
Rule: read EVERY entry's body and its callers before deciding. Do not decide from the name or comment alone; do not skim.
For each entry decide, using the body AND how callers use it (arguments passed, result used, the caller's own name and job):
- CONFIRM: the name fits.
- RENAME: a clearly better name (same style: lowercase module prefix + CamelCase, letters digits underscore, no _<number> suffix; Sony SDK names like sceGs/sceDma/scePad/sceSif only when the behaviour clearly matches).
- UNSURE: still not enough evidence. Keep it.
Write each verdict line exactly:
<PROG> 0x<addr> <oldname> CONFIRM|RENAME|UNSURE <newname or oldname> <short reason, one line>
Every entry gets exactly one line. Do not quote game text longer than 3 words.
